## 🔴 إجراءات مطلوبة منك — لا أستطيع تنفيذها

### 1. أغلق القاعدة المفتوحة في المشروع المشترك *(الأهم — الآن)*

هذه هي الثغرة الحقيقية. حذف الرموز من الكود **لا يغلقها**.

اذهب إلى: **Firebase Console → مشروع `marine-command-center` → Firestore → Rules**

⚠️ **لا تستبدل الملف كاملًا، ولا تنسخ `config/firestore.rules` هنا.**
تلك القواعد مخصّصة للمشروع الجديد، ونسخها هنا قد يعطّل تطبيق Red Sea Marine.

**المطلوب فقط:** احذف البلوك الذي يسمح بالوصول لمجموعات `fam_*`. شكله تقريبًا:

```javascript
function isFamily(coll) {
  return coll.matches('fam_.*');
}

match /{coll}/{docId} {
  allow read, write: if isFamily(coll);
}
```

احذف هذين المقطعين واترك بقية القواعد كما هي، ثم **Publish**.

> قواعد Firestore تعمل بمنطق "السماح يغلب": المجموعة التي لا تملك قاعدة
> `allow` صريحة تُرفض تلقائيًا. فحذف البلوك وحده كافٍ لإغلاق `fam_*` دون
> المساس بأي قاعدة أخرى.

**للتحقق:** بعد النشر، افتح الرابط المنشور و F12 → Console. أي محاولة قراءة
من `fam_users` يجب أن تُرجع `permission-denied`.

### 2. اعتبر الرمز `343516` محروقًا نهائيًا

الرمز موجود في **تاريخ git العام** منذ أول commit. حذفه من الكود لا يمحوه
من التاريخ، وGitHub قد يكون خزّن نسخًا من الـ commits القديمة.

**المطلوب:** إذا كنت تستخدم `343516` في أي مكان آخر (جهاز، حساب، تطبيق)،
**غيّره الآن**. لا تُعِد استخدامه في هذا المشروع أو غيره.

الأمر نفسه ينطبق على `1111` و`2222` — رموز أطفال تجريبية، لكن لا تُعَد
استخدامها.

### 3. أنشئ مشروع Firebase مخصّصًا

**Firebase Console → Add project** (مثلًا `family-game-center`).

- فعّل **Firestore Database** (وضع الإنتاج).
- فعّل **Authentication ← Sign-in method ← Email/Password**.
- **Rules** → انسخ `config/firestore.rules` → **Publish**.
- أضف تطبيق ويب، وانسخ الإعدادات إلى `.env.local` (وإلى متغيّرات
  المستودع للنشر — راجع `docs/DEPLOY.md`).

لا تربطه بأي مشروع أعمال. القواعد ومفاتيح الخدمة والنسخ الاحتياطي كلها على
مستوى المشروع — المشاركة تعني أن خطأً في تطبيق العائلة يعرّض بيانات العمل.

---

### 4. حذف بيانات `fam_*` من المشروع المشترك *(اختياري)*

بما أن القرار "بداية نظيفة" ولن تُرحَّل البيانات، احذف مجموعات `fam_*`
من `marine-command-center` بعد إغلاق القواعد. هذا يقلّل مساحة الخطر ويمنع
أي التباس لاحق.

## ⏭️ ما يأتي بعد ذلك (المرحلة 1)

**قرار عالق يحتاج جوابك:** Cloud Functions تتطلب خطة **Blaze**، وهي تحتاج
بطاقة ائتمانية حتى لو كان الاستهلاك صفرًا. بحجم الاستخدام المتوقع (عائلة
وأصدقاء) الفاتورة ستكون **$0 فعليًا** — الحصة المجانية تغطي 2 مليون استدعاء
شهريًا. لكن بدون Blaze **لا يوجد خادم**، وبالتالي:

- لا يمكن تطبيق "سلطة الخادم على النقاط" التي تشترطها وثيقة الفريق.
- تبقى الألعاب في وضع **free play** بلا نقاط رسمية (وهو ما اخترته أصلًا
  للمرحلة الأولى — فقد نبدأ بهذا المسار دون Blaze).

المسار المقترح للمرحلة 1 بلا تكلفة:
Firebase Auth (مجاني) + Firestore (مجاني ضمن الحصة) + قواعد أمان محكمة،
مع تأجيل Cloud Functions والنقاط الرسمية حتى تتضح الحاجة.


لأنها تتطلب خادمًا). 37 اختبارًا في `tests/rules/` **وقتَها**، أغلبها سلبي.
(نمت المجموعة لاحقًا — الرقم الحالي في `README.md`.)

**تُحقّق من هذه الثوابت:**

| الثابت | مُختبَر |
|---|---|
| الزائر غير المسجّل لا يقرأ ولا يكتب شيئًا | ✅ |
| العضو لا يقرأ أو يعدّل بيانات عضو آخر | ✅ |
